# 7. Trace ingestion and deduplication

Date: 2026-10-28

## Status

Accepted

## Context

Praxis needs to discover crux traces from the filesystem, evaluate them, and
apply improvements. Traces are generated by crux pipelines and stored as JSON
files. Re-running ingestion on the same traces should be idempotent.

## Decision

- `TraceSource` trait (port) defines `discover() -> Result<TraceDiscovery, TraceSourceError>`
- `FileTraceSource` (adapter) recursively walks directories for JSON files,
  validates each as a `Crux` trace, returns `DiscoveredTrace` entries
- `IngestionLedger` trait tracks processed trace IDs for cross-run deduplication
- `FileIngestionLedger` persists processed IDs alongside the strategy file
- `ingest_traces()` sorts traces chronologically, deduplicates within a scan
  using a `HashSet`, skips already-ingested traces via the ledger, and processes
  each new trace through the improvement loop
- Failed cycles are captured in `IngestionReport::failures` without aborting
  the run

## Consequences

- Ingestion is idempotent across runs (no reprocessing)
- Traces are processed in chronological order for meaningful trend analysis
- Individual failures don't abort the entire run
- The ledger file uses `set_extension("ingested.json")` for clean naming
- Symbolic links are skipped for security
